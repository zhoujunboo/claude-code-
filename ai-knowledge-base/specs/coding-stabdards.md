# 编码规范

## 要做什么

- 新增和修改代码统一使用 TypeScript。
- 使用 `strict` 模式。
- 变量、函数用 `camelCase`，类型和接口用 `PascalCase`。
- 函数参数、返回值、核心数据结构都要有明确类型。
- 优先用 `interface` 定义领域对象，用 `type` 定义联合类型。
- 异步逻辑统一使用 `async/await`。
- 外部数据先做映射和约束，再进入业务逻辑。
- 默认使用具名导出。
- 保持单一职责，优先做最小修改。

## 不做什么

- 不混入 Python 或其他语言规范。
- 不使用 `any` 逃避类型问题；无法确定时用 `unknown`。
- 不把外部原始响应直接传入业务逻辑。
- 不硬编码密钥、Token、环境地址。
- 不为了通用性过度抽象。
- 不在一个函数里混合请求、转换、校验和业务决策。
- 不修改与当前任务无关的逻辑和结构。

## 边界 & 验收

- 本规范只约束 TypeScript 编码，不包含页面、样式和组件设计。
- 只覆盖新增和修改代码，不强制重写历史代码。
- 验收以类型完整、职责清晰、改动最小为主。
- 出现 `any`、隐式输入结构、未映射外部数据，视为不通过。

## 怎么验证

- 人工检查新增代码是否为 TypeScript。
- 人工检查参数、返回值、核心对象是否显式声明类型。
- 人工检查是否存在 `any`、默认导出、硬编码配置。
- 人工检查异步逻辑是否统一使用 `async/await`。
- 人工检查外部数据是否先转换为内部 `camelCase` 结构再使用。
